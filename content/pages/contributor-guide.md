## 1. Pick an idea

Read the [ideas list](/ideas/) and choose one or two that match your skills
and interests. Each idea page lists the repository, skills and mentors.

## 2. Set up the project

Set up the repository from a clean checkout. You should not need any Elixpo
secret, production account or paid API key to build the code and run the
tests that matter for your idea.

| LixBlogs | [elixpo/blogs.elixpo](https://github.com/elixpo/blogs.elixpo) | [README](https://github.com/elixpo/blogs.elixpo/blob/main/README.md), [.env.example](https://github.com/elixpo/blogs.elixpo/blob/main/.env.example), [CONTRIBUTING](https://github.com/elixpo/blogs.elixpo/blob/main/CONTRIBUTING.md) |

If setup fails or asks for a secret, that is a bug. Tell us in an issue or in
Discussions, with the exact command and error. Fixing setup is a good first
contribution.

## 3. Make a small contribution

Fix a small bug, improve a test, or clarify documentation in the repository
for your idea. Keep it small and finish it: a merged ten-line change tells us
more than an unfinished large one.

- Explain what you changed and how you tested it.
- If you used AI tools in a meaningful way, say so in the pull request. Read
  our [AI policy](/ai-policy/).
- Respond to review comments. Review is how we work together.

## 4. Talk to us in public

- Ask questions and introduce yourself in
  [GitHub Discussions](https://github.com/orgs/elixpo/discussions).
- Report bugs in the issue tracker of the relevant repository.
- Please don't send private messages to mentors about the project. Public
  questions help the next person too.

Mentors aim to reply within 48 hours on weekdays. If you have waited longer,
post a polite reminder in the same thread.

## 5. Write your proposal

Use the [proposal template](/proposal/) and read how we
[select contributors](/selection/).

## Code of Conduct

Everyone taking part follows the
